# Intents

Part of the [knowledge graph](../../README.md), business layer.
Every file here but this one is a node of kind `intent`, named in kebab-case.

An intent node states an enduring outcome the product commits to, why it matters, and links down to the rules and flows that deliver it.
`describes` is forbidden; `verified` is required.

## Nodes

One line per node, sorted by file name.

- [A request can only do what its session may](a-request-can-only-do-what-its-session-may.md) - the session says who is asking, the market's role what they may do, and the server decides both
- [Every approved vendor gets a table by the market's rules](every-approved-vendor-gets-a-table-by-the-markets-rules.md) - seated by the rules and their own answers, told why when not, changeable by hand
- [Reviewing applications as a team](reviewing-applications-as-a-team.md) - several reviewers at once, every verdict named, follow-ups owned, settled when the assignment begins
- [Results go out once, and settle the allocation](results-go-out-once-and-settle-the-allocation.md) - published after a current run, which it settles; an applicant reads a table or none
- [The door on market day](the-door-on-market-day.md) - who is expected, who has arrived, check-in by either side; afterwards the market is a record
- [The market's phase says what to do next](the-markets-phase-says-what-to-do-next.md) - one phase, one next step said before the click, each path its own sequence
- [Vendors apply on the market's own page](vendors-apply-on-the-markets-own-page.md) - a code instead of an account, and no applicant surface where the organizer did not turn it on
